# Bug Hunt Report: STT 405 Method Not Allowed (Holistic)

## Scope

**Bug under investigation:** STT feature returns HTTP 405 (Method Not Allowed) when tested from a phone over HTTPS (`https://pandora.twin-bramble.ts.net`). Reported as working locally over HTTP.

**Files read in full:**
- `nginx/nginx.conf` -- NGINX reverse proxy config (166 lines on host)
- `nginx/entrypoint.sh` -- TLS mode selection at container startup
- `nginx/tls-include.conf` -- TLS directives (listen 443 ssl + ciphers)
- `nginx/tls-include-empty.conf` -- empty placeholder for HTTP-only mode
- `services/stt/main.py` -- FastAPI STT service (POST /transcribe, GET /health)
- `services/stt/backends/__init__.py` -- TranscribeResult dataclass
- `services/stt/backends/cpu.py` -- faster-whisper CPU inference backend
- `services/stt/Dockerfile` -- container build (bakes in base.en model)
- `services/stt/requirements.txt` -- Python deps
- `frontend/stt.js` -- browser-side voice capture, WAV encoding, _sendToSTT
- `frontend/stt-worklet.js` -- AudioWorklet processor for PCM accumulation
- `frontend/app.js` -- main app (initSTT integration, lines 2764-2768)
- `docker-compose.yml` -- full stack definition (7 services)
- `.env` -- TLS_MODE=tailscale, TLS_CERT_DIR=/srv/geographica/tls/tailscale

**Approach:** Read every source file in the request path (browser -> NGINX -> FastAPI -> Whisper backend), then compared the on-disk config against the live container config to explain why the code looks correct but requests fail.

## Bugs

### 1. Stale bind mount: container's nginx.conf is missing the /stt/ location block

**Location:** `docker-compose.yml:189` (bind mount), `nginx/nginx.conf:91-99` (missing block)
**Severity:** critical
**Evidence:**

The host file `nginx/nginx.conf` has 166 lines and contains the `/stt/` location block at lines 91-99:
```nginx
location /stt/ {
    proxy_pass http://stt:8000/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    client_max_body_size 2m;
    proxy_read_timeout 30s;
}
```

The file inside the running container at `/etc/nginx/conf.d/default.conf` has only 155 lines and zero occurrences of the string "stt". The `nginx -T` dump confirms the loaded config jumps from `/search/` directly to `/admin/status` with no `/stt/` block.

The container was created at `2026-04-08T11:43:26 UTC`. The git commit adding the `/stt/` block was made later the same day. Git commit operations create new file inodes on disk. Docker file bind mounts (`./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro`) track the original inode. When git wrote the new inode, the container continued reading the old one.

**Impact:** Without the `/stt/` location block in the loaded NGINX config, all requests to `/stt/*` fall through to `location /` (line 10):
```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```
- **GET** requests (e.g., `/stt/health`) -- `try_files` serves `index.html` with HTTP 200. The 10,616-byte response body in the access log matches the index.html size exactly. This silently masks the failure as a "healthy" response.
- **POST** requests (e.g., `/stt/transcribe`) -- NGINX's static file handler rejects POST with **HTTP 405 Not Allowed**. This is the reported bug.

This bug is **not** HTTPS-specific. Testing confirmed 405 on both HTTP (port 8093) and HTTPS (port 443) from the host. The user observed it only on HTTPS because the phone only accesses via HTTPS.

**Fix:** `docker compose restart frontend` (or `docker compose up -d --force-recreate frontend`) to re-establish the bind mount with the current inode. Going forward, any edit to `nginx/nginx.conf` requires a frontend container restart.

### 2. STT container does not exist

**Location:** `docker-compose.yml:142-163`
**Severity:** critical
**Evidence:**

`docker compose ps stt` returns no output. `docker logs geographica-stt` returns "No such container." `docker images | grep stt` returns nothing. The STT service image was never built.

Even after fixing Bug #1 (restarting frontend to load the correct nginx.conf), NGINX will fail to resolve the `stt` hostname at config load time because there is no container providing that DNS entry. NGINX will either refuse to start entirely or return 502 Bad Gateway.

**Impact:** The STT feature cannot function at all. The fix requires: `docker compose build stt && docker compose up -d stt && docker compose restart frontend`.

### 3. Frontend error handler does not detect the SPA-fallback 405 scenario

**Location:** `frontend/stt.js:417-435` (`_sendToSTT` fetch response handling)
**Severity:** minor
**Evidence:**

The response handler checks for specific status codes (413, 422, 502, 503, 504) but falls through to a generic message for 405:
```javascript
if (!resp.ok) {
    throw new Error('STT request failed (' + resp.status + ')');
}
```

When NGINX serves 405 from the static file handler, the response has `Content-Type: text/html` and `Server: nginx`. The handler could detect this and show a more helpful message like "Voice search service unavailable" instead of the opaque "STT request failed (405)".

More importantly, there is no response content-type check. If a GET to `/stt/health` returns 200 with HTML (as happens in the Bug #1 scenario), any health-check logic that only checks `resp.ok` would incorrectly conclude the service is healthy.

**Impact:** Poor user experience when the STT service is down. The user sees a confusing error code instead of actionable information.

## Design Concerns

### NGINX fails entirely when any upstream is unresolvable

With hardcoded hostnames in `proxy_pass`, NGINX resolves DNS at config parse time. If the `stt` (or `gps`, `search`, etc.) container is down when the frontend restarts, NGINX will fail with `host not found in upstream "stt:8000"` and refuse to start. This takes down the entire frontend -- including all working services -- because one optional service is unavailable.

The standard mitigation is to use a `resolver` directive with a variable:
```nginx
location /stt/ {
    resolver 127.0.0.11 valid=30s;
    set $stt_upstream http://stt:8000;
    proxy_pass $stt_upstream;
    ...
}
```
This defers DNS resolution to request time. NGINX starts regardless of upstream state and returns 502 for unavailable services.

### File bind mounts are fragile across git operations

The `docker-compose.yml` mounts individual files (e.g., `./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro`). Any git operation that replaces the file (commit, checkout, rebase, merge, stash pop) creates a new inode, silently breaking the mount. This affects **all** file bind mounts in the compose file, not just nginx.conf.

**Mitigation:** Mount the directory instead of the file. For example, mount `./nginx/` to `/etc/nginx/geo/` and use `include /etc/nginx/geo/nginx.conf;` from the main config. Directory mounts survive inode changes because Docker tracks the directory inode, which remains stable.

### Inconsistent Host header in /stt/ location block

The `/stt/` location (line 95) uses `proxy_set_header Host $host`, while every other proxy location uses `$http_host`. The difference: `$host` strips the port, `$http_host` preserves it. On standard ports (80/443) they're equivalent, but this inconsistency is a maintenance hazard and could cause issues if non-standard ports are ever used.
